# RK3566 模型验证记录 · 2026-11-08

环境为 ARM64 RK3566 / fnOS，约 3.8GiB 内存、RKNPU 驱动 0.9.8、`librknnrt.so` 与 Lite2 2.3.2。这里摘录 SingVerse 的当日实测；不包含用户音频、私有地址、凭据或原始日志。完整服务验证记录位于 SingVerse 的 `services/singverse-compute/VERIFICATION.rk3566-2026-11-08.md`。

## 转换

UVR ONNX 来源为 sherpa-onnx 的 `source-separation-models` 发布文件，29,704,738 字节，SHA-256 `9d78f8566fa8198065214ab628be1de966a500c57786695aa4b13e2b27a7727d`。

使用独立转换环境 Toolkit2 2.3.2 / Python 3.12 / Torch 2.2.0 / ONNX 1.16.1 / NumPy 1.26.4 / Protobuf 4.25.4 / SciPy 1.13.1。固定输入 `[1, 4, 2048, 256]`，target `rk3566`。FP16 不做量化；INT8 使用 W8A8、normal 算法、channel 方法，校准取自自备 112 秒音频 20 / 40 / 60 / 80 秒处，首 8 秒留作对照。校准音频与张量不分发；本仓库发布确切的已生成 INT8 文件，不声称可用公开数据重建同一量化结果。

## 性能与数值对照

FP16 对 112.066667 秒双声道 44.1kHz WAV 完成全曲分离，耗时 662.046 秒、峰值进程 RSS 706.14MiB。人声和伴奏输出各 4,942,140 帧，无 OOM 或应用后端降级。

对同一首歌前 8 秒，在相同 2 核 CPU / 1280MiB 容器预算 / 单 DSP 线程下：

| 模型 | 分离阶段 | RKNN 调用合计 | 峰值进程 RSS |
| --- | ---: | ---: | ---: |
| FP16 | 63.791 秒 | 62.650 秒 | 554.46MiB |
| INT8 | 49.360 秒 | 48.207 秒 | 433.24MiB |
| INT4 W4A16 | 不支持 | 未测 | 未测 |

分离阶段包含频谱处理、推理和写 WAV，不含 Python 依赖导入与模型初始化。INT8 阶段耗时降低约 22.62%，仅测 8 秒，不能当作整曲或实时性能。

FP16 首块 5.828209 秒输出相对 ONNX CPU：人声 RMS 误差 0.0982%、伴奏 0.1246%，相关系数约 0.999999。INT8 留出 8 秒：人声误差 33.9452%、伴奏 41.4115%，相关系数 0.940760 / 0.923495、SNR 9.38 / 7.66dB。INT8 未通过数值质量检查，不建议作为用户使用模型。FP16 数值接近参考不等同于全曲或主观音质验收。

INT8 之后以目标 rk3566 尝试 W4A16 / group32。SDK 在 config 阶段拒绝：`The quantized_dtype = 'w4a16' not support in 'rk3566'!`。没有生成 INT4 文件，结论限于当前芯片和 Toolkit2 2.3.2。

## 验证边界

神经网络卷积等算子在 NPU，STFT、拼接等在 CPU；转换报告还有 46 个 CPU Transpose，不能称为全图纯 NPU。以上通过的是无网络、只读媒体 / 模型、受限 UID 的临时隔离 CLI；默认容器环境下正式管理服务的 NPU 初始化仍失败，不能据此标为 READY。未在模型仓库中放宽部署安全配置。

没有 RK3568 / RK3588 板端验证，没有 INT8 全曲或多歌曲质量验证，也没有 INT4 性能结果。工作流验证下载、摘要、包格式与设备映射，不代替这些硬件验收。
